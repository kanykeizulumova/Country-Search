# Архитектура и дизайн Country Search (`DESIGN.md`)

В данном документе описаны ключевые архитектурные решения, обоснования параметров, анализ алгоритмической сложности и применённые принципы чистого кода в проекте **Country Search**.

---

## 1. Механизм отмены устаревших запросов (Race Condition Prevention)

### Как устроена отмена

Для предотвращения гонки устаревших ответов (race condition) используется встроенный браузерный API `AbortController`:

1. **Немедленная отмена на каждый ввод пользователя:**  
   В слушателе события `input` (`src/index.ts`) при каждом нажатии клавиши **до** срабатывания таймера `debounce` вызывается `currentController.abort()`. Это гарантирует, что если предыдущий сетевой запрос уже летит к серверу, он прерывается сразу в момент изменения поисковой строки.
2. **Комбинирование с таймаутом в чистом слое Core:**  
   При фактическом старте поиска создаётся новый экземпляр `new AbortController()`. Вся работа по связыванию сигналов вынесена в чистую функцию бизнес-логики `getCountryList(query, signal, timeoutMs)` (`src/api/getCountryList.ts`). С помощью `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])` объединяются два сценария прерывания:
   - Пользователь продолжил ввод или стёр текст (отмена через `currentController.abort()`).
   - Сервер не отвечает более 5 секунд (прерывание по таймауту).
3. **Разделение типов ошибок в `catch`:**
   - Если `error.name === 'AbortError'` — запрос отменён приложением. Это штатное поведение живого поиска, пользователю ошибка **не показывается**, интерфейс не мерцает.
   - Если произошёл таймаут (`TimeoutError`), ошибка сервера (`HttpError`) или потеря соединения (`TypeError: Failed to fetch`) — в `handleSearch` отображается дружелюбный блок с кнопкой «Повторить».

### Почему отмена через `AbortController` вместо фильтрации ответов постфактум

Согласно требованиям ТЗ, гонка запросов устраняется именно через физическую отмену `currentController.abort()`, а не «маскировкой» (например, сравнением текста ответа с текущим значением `input.value` или отслеживанием времени прихода ответа).

Реализация через `currentController` в оркестраторе `src/index.ts` и `getCountryList` в `src/api/getCountryList.ts` выбрана по следующим причинам:

- **Физический разрыв сетевого соединения:**  
  Фильтрация постфактум всё равно заставляет браузер загружать данные устаревшего ответа, расходовать трафик и парсить JSON. Вызов `currentController.abort()` немедленно прерывает сетевой запрос в браузере.
- **Освобождение пула сетевых соединений:**  
  Браузер имеет ограничение на число одновременных HTTP-соединений к одному домену. Своевременный `abort()` мгновенно освобождает сокет для следующего актуального запроса, предотвращая очередь (head-of-line blocking).
- **Чистота логики в `src/index.ts`:**  
  Вся отмена локализована в одном месте: при каждом событии `input` проверяется и отменяется `currentController`, а в блоке `catch` ошибка `err.name === 'AbortError'` просто игнорируется, не засоряя экран ложными ошибками.

## 2. Обоснование задержки `debounce` (400 мс)

Функция `debounce` (`src/utils/debounce.ts`) откладывает сетевой запрос на **400 мс**:

- **Почему именно 400 мс:**  
  Средняя скорость набора текста человеком составляет примерно 180–300 символов в минуту, что соответствует паузе между ударами по клавишам около 200–350 мс. Задержка в 400 мс даёт пользователю возможность комфортно ввести осмысленную часть слова (например, `"spa"` или `"spain"`), не инициируя сетевые запросы на каждой промежуточной букве.
- **Что будет, если убрать debounce (0 мс):**  
  При каждом нажатии клавиши будет создаваться сетевой запрос. Даже при моментальной отмене предыдущего запроса через `AbortController`, браузер будет отправлять множество HTTP-запросов на сервер. Это ведёт к риску получения ошибки **HTTP 429 Too Many Requests (Rate Limit)** от публичного API, лишнему расходу заряда батареи и мерцанию спиннера.
- **Что будет, если сильно увеличить задержку (> 1000 мс):**  
  При задержке в 1 секунду и более приложение теряет ощущение «живого» поиска. Пользователю кажется, что интерфейс завис или не работает, что провоцирует лишние клики или перезагрузку страницы.
- **Баланс:**  
  Задержка 400 мс в сочетании с немедленной отменой активного запроса при вводе обеспечивает идеальный баланс: отсутствие лишней нагрузки на сервер и мгновенную отзывчивость интерфейса.

## 3. Оценка алгоритмической сложности (Big O)

### 3.1. Функция `mapCountryResponse` (`src/utils/mapCountryResponse.ts`)

Функция преобразует «сырой» DTO из API в строго типизированный объект `CountryData`:

- **Временная сложность (Time Complexity):**
  - Извлечение примитивных полей (`name`, `flag`, `capital`, `region`, `population`, `area`): $\mathcal{O}(1)$.
  - Обработка языков `languages.map(...)`: $\mathcal{O}(L)$, где $L$ — количество официальных языков страны (на практике $L \le 5$).
  - Обработка валют `currencies.map(...)`: $\mathcal{O}(C)$, где $C$ — количество валют страны (на практике $C \le 3$).
  - Обработка границ `borders.slice(...)`: $\mathcal{O}(B)$, где $B$ — количество сухопутных границ (на практике $B \le 14$).
  - **Итог:** $\mathcal{O}(L + C + B)$. Поскольку массивы $L, C, B$ ограничены небольшими константами реального мира, для одной страны сложность фактически составляет **$\mathcal{O}(1)$**.  
    При маппинге списка из $N$ полученных от сервера стран суммарная сложность составляет **$\mathcal{O}(N)$**.
- **Пространственная сложность (Space Complexity):**  
  $\mathcal{O}(N)$ — создаётся новый нормализованный массив объектов без изменения исходных данных (иммутабельность).

### 3.2. Функция `debounce` (`src/utils/debounce.ts`)

- **Временная сложность:** $\mathcal{O}(1)$ — вызовы `clearTimeout` и `setTimeout` выполняются за константное время.
- **Пространственная сложность:** $\mathcal{O}(1)$ — в замыкании хранится единственный идентификатор таймера `timeoutId`.

### 3.3. Рендеринг карточек (`src/ui/card.ts`)

- Отрисовка $N$ карточек через DOM API: $\mathcal{O}(N)$ по времени и памяти. Создание элементов через `document.createElement` без парсинга HTML-строк работает значительно быстрее, чем `innerHTML`.

## 4. Принципы чистого кода (Clean Code)

В архитектуре проекта соблюдены фундаментальные инженерные практики:

1. **KISS (Keep It Simple, Stupid):**
   - Функция `debounce` (`src/utils/debounce.ts`) решена через лаконичное замыкание с правильной TS-типизацией без оверинжиниринга и избыточных настроек (`leading`/`maxWait`).
   - Каркас приложения не перегружен сложными стейт-менеджерами: всё состояние управляется прозрачно через локальные переменные `currentController` и `lastQuery` в `src/index.ts`.

2. **Single Responsibility Principle (SRP / Принцип единственной ответственности):**
   - `src/api/getCountryList.ts` — сервисная функция Core (бизнес-логика), объединяющая сигнал отмены и таймаут (`AbortSignal.any`), выполнение запроса `searchCountries` и маппинг `mapCountryResponse`. Возвращает готовые `CountryData[]` без малейшей зависимости от DOM.
   - `src/api/searchCountries.ts` — отвечает исключительно за сетевой запрос к эндпоинту, обработку HTTP-статусов (200, 404) и проброс `AbortSignal`.
   - `src/api/HttpError.ts` — специализированный класс ошибок для представления HTTP-статусов, расширяющий стандартный `Error`.
   - `src/utils/mapCountryResponse.ts` — чистая функция (pure function), отвечающая только за преобразование и валидацию данных.
   - `src/ui/card.ts` — отвечает исключительно за конструирование DOM-структуры карточки страны и её аккордеона.
   - `src/ui/view.ts` — фабрика базовых элементов интерфейса (поле поиска, спиннер, сообщение 404, блок ошибки с кнопкой повтора).
   - `src/index.ts` — UI-оркестратор (`handleSearch`), который управляет событиями ввода, состояниями экрана (спиннер, ошибки, карточки) и вызывает Core-сервисы.

3. **DRY (Don't Repeat Yourself):**
   - Вспомогательная функция `createRow(label, value)` в `src/ui/card.ts` устраняет дублирование вёрстки для 7 параметров страны (столица, регион, население, языки, валюта, площадь, границы).
   - Интерфейсы `RawCountry` и `CountryData` вынесены в `src/types/country.ts` и переиспользуются во всех модулях и тестах.

4. **Separation of Concerns (Строгое разделение слоёв Core и UI):**
   - **Слой Core (бизнес-логика):** `getCountryList.ts`, `searchCountries.ts`, `HttpError.ts`, `mapCountryResponse.ts`, `debounce.ts`. Этот слой не знает о существовании DOM (`document`, `window`, `HTMLElement`), содержит только чистые функции и тестируется в легковесной среде Node.js по принципу FIRST без необходимости запускать `jsdom`.
   - **Слой UI (представление):** `ui/card.ts`, `ui/view.ts`, `src/index.ts`. UI имеет право обращаться к Core для получения данных, но Core никогда не зависит от UI и ничего не знает о визуальном представлении. Внутри UI-оркестратора `handleSearch` логика получения данных отделена от логики отрисовки.

5. **Безопасность и отказ от небезопасных практик:**
   - Полное отсутствие `innerHTML` и `insertAdjacentHTML` исключает риск XSS-уязвимостей. Все динамические значения вставляются исключительно через `textContent`.
